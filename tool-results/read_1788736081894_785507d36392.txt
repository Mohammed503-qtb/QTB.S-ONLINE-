     1→# PLAN.md — متجر تجارة إلكترونية متكامل لليمن
     2→
     3→## 0. تعريف المشروع
     4→
     5→هذا المشروع عبارة عن تطبيق تجارة إلكترونية موحد مبني بـ Flutter، يعمل على Android وiPhone، ويقدم واجهة العميل وواجهة الإدارة والتشغيل داخل نفس التطبيق بحسب صلاحيات المستخدم.
     6→
     7→الهدف ليس بناء واجهة متجر فقط، بل بناء دورة تجارية مترابطة End-to-End تبدأ من عرض المنتج وتنتهي بالتسليم أو الإرجاع والتسوية المالية، مع إدارة المخزون والحسابات البنكية والمحتوى والصلاحيات والإصدارات وحالة التطبيق من مكان واحد.
     8→
     9→النظام يجب أن يكون عمليًا، واضحًا، قابلًا للتوسع، ولا يحتوي على وظيفة معزولة لا تعرف من أين تأتي بياناتها أو إلى أين تذهب نتيجتها.
    10→

    12→
    13→# 1. مبادئ المشروع غير القابلة للكسر
    14→
    15→## 1.1 Flutter
    16→
    17→- التطبيق العميل والإدارة داخل مشروع Flutter واحد ما لم يظهر سبب تقني قوي للفصل.
    18→- Android وiPhone هدفان أساسيان.
    19→- الواجهة عربية RTL من البداية مع دعم تعدد اللغات لاحقًا.
    20→- دعم الوضع الفاتح والداكن.
    21→
    22→## 1.2 Backend هو مصدر الحقيقة
    23→
    24→الهاتف لا يكون مصدر الحقيقة للبيانات الحساسة.
    25→
    26→مصدر الحقيقة النهائي:
    27→- الأسعار.
    28→- المخزون.
    29→- الطلبات.
    30→- المدفوعات.
    31→- صلاحيات المستخدمين.
    32→- الحسابات المالية.
    33→- إعدادات المتجر.
    34→- Feature Flags.
    35→- حالة الإصدار.
    36→
    37→التطبيق يحتفظ Cache محليًا لتحسين السرعة، لكنه لا يقرر وحده العمليات الحساسة.
    38→
    39→## 1.3 كل عملية مالية قابلة للتتبع
    40→
    41→كل دفع أو استرداد أو مصروف أو حركة بنك يجب أن يكون لها:
    42→- رقم مرجعي.
    43→- الوقت.
    44→- المستخدم/الجهة المنفذة.
    45→- الحالة.
    46→- سبب التعديل عند الحاجة.
    47→- سجل Audit.
    48→
    49→## 1.4 عدم الحذف المدمر
    50→
    51→السجلات المالية والطلبات وحركات المخزون لا تُحذف حذفًا نهائيًا في التشغيل العادي.
    52→تستخدم حالات Cancelled / Rejected / Archived / Reversed حسب نوع السجل.
    53→
    54→## 1.5 عدم ازدواج العمليات
    55→
    56→إنشاء الطلب والدفع وحجز المخزون والـ Refund يجب أن تكون Idempotent بحيث لا يؤدي الضغط المتكرر أو إعادة المحاولة بسبب الشبكة إلى إنشاء عملية ثانية.
    57→
    58→## 1.6 لا ثقة في بيانات العميل الحساسة
    59→
    60→الخادم يعيد حساب:
    61→- سعر المنتج.
    62→- الخصومات.
    63→- الشحن.
    64→- الإجمالي.
    65→- أهلية الكوبون.
    66→- توفر المخزون.
    67→
    68→## 1.7 كل حالة لها انتقالات معروفة
    69→
    70→لا توجد شاشة تغيّر حالة سجل إلى قيمة عشوائية.
    71→كل Entity حساس له State Machine واضحة، ولكل انتقال شروط وصلاحيات وآثار جانبية.

   146→# 4. الأدوار
   147→
   148→## CUSTOMER
   149→
   150→التصفح، السلة، الطلب، الدفع، التتبع، الإرجاع، الملف الشخصي، التواصل.
   151→
   152→## SUPER_ADMIN
   153→
   154→كل الصلاحيات النظامية، بما فيها إدارة الصلاحيات والإعدادات الحرجة والإصدارات والنسخ الاحتياطية.
   155→
   156→## MANAGER
   157→
   158→تشغيل المتجر والمنتجات والطلبات والمخزون والعملاء والتقارير وفق الصلاحيات.
   159→
   160→## ACCOUNTANT
   161→
   162→المدفوعات، الحسابات البنكية، المصروفات، الاستردادات، المشتريات، والتقارير المالية.
   163→
   164→## WAREHOUSE
   165→
   166→التجهيز والمخزون والحركات والتعبئة والاستلام والتسليم للشحن.
   167→
   168→## CONTENT_MANAGER
   169→
   170→المنتجات، التصنيفات، البنرات، الصفحة الرئيسية، المحتوى والعروض وفق الصلاحيات.
   171→
   172→## DELIVERY_OPERATOR
   173→
   174→الشحن، الحالات اللوجستية، ومحاولات التسليم فقط.
   175→
   176→لا تُكتب الصلاحيات داخل الواجهة فقط؛ يتم فرضها على الخادم أيضًا.

   180→# 5. التجربة الموحدة داخل التطبيق
   181→
   182→عند فتح التطبيق:
   183→
   184→```text
   185→Splash
   186→  ↓
   187→Load Remote Config
   188→  ↓
   189→Check Maintenance
   190→  ↓
   191→Check Minimum Version
   192→  ↓
   193→Restore Session
   194→  ↓
   195→Resolve Role
   196→  ↓
   197→Customer Shell OR Admin/Operations Shell
   198→```
   199→
   200→إذا كانت هناك مشكلة حرجة:
   201→- الصيانة تمنع الوظائف المحددة فقط أو التطبيق كاملًا حسب الإعداد.
   202→- Force Update يمنع الاستخدام عند تجاوز الحد الأدنى.
   203→- Emergency Stop يمكنه إيقاف الطلبات والدفع أو التطبيق بالكامل مع إبقاء شاشة الصيانة.

   229→## قواعد
   230→
   231→- لا يعتمد التطبيق على قيمة قديمة بلا مدة صلاحية مناسبة.

   233→- لا يمكن لـ Remote Config تجاوز صلاحيات المستخدم.

   479→# 15. إنشاء الطلب End-to-End
   480→
   481→1. العميل يفتح Checkout.
   482→2. التطبيق يرسل المنتجات والـ variants والكميات والعنوان وطريقة الشحن.
   483→3. الخادم يعيد قراءة المنتجات والأسعار.
   484→4. الخادم يتحقق من أن المنتجات نشطة.
   485→5. الخادم يتحقق من المخزون القابل للحجز.
   486→6. يحسب الخصومات.
   487→7. يتحقق من الكوبون.
   488→8. يحسب الشحن.
   489→9. يحسب الإجمالي النهائي.
   490→10. ينشئ Order Number.
   491→11. ينشئ Payment Reference.
   492→12. ينشئ Tracking Code عند السياسة المناسبة.
   493→13. ينشئ حجز مخزون أو يحجز في نفس Transaction المنطقية.
   494→14. يسجل Order Event.
   495→15. يعيد بيانات الطلب للعميل.
   496→
   497→إذا فشلت العملية قبل Commit، لا ينتج طلب جزئي غير صالح ولا حجز يتيم.

   570→# 18. تدفق الدفع الكامل
   571→
   572→```text
   573→Order Created
   574→↓
   575→Payment Reference Generated
   576→↓
   577→Customer sees bank/wallet account
   578→↓
   579→Customer transfers funds externally
   580→↓
   581→Customer returns to app
   582→↓
   583→Submits transfer data + proof if available
   584→↓
   585→Payment = UNDER_REVIEW
   586→↓
   587→Accountant/authorized operator reviews
   588→↓
   589→VERIFY / REJECT / REQUEST_CLARIFICATION
   590→```
   591→
   592→عند VERIFY:
   593→- payment status = VERIFIED.
   594→- order payment state updates.
   595→- accounting transaction is posted.
   596→- order moves to next valid state.
   597→- notification is generated.
   598→- audit log is written.
   599→
   600→عند REJECT:
   601→- سبب إلزامي.
   602→- payment remains auditable.
   603→- order stays payable or moves to payment issue state حسب السياسة.
   604→
   605→---
   606→
   607→# 19. حالات الدفع غير الطبيعي
   608→
   609→## دفع ناقص
   610→
   611→```text
   612→Expected 50,000
   613→Received 45,000
   614→```
   615→
   616→الحالة PARTIALLY_PAID، والرصيد المتبقي 5,000.
   617→
   618→## دفع زائد
   619→
   620→```text
   621→Expected 50,000
   622→Received 55,000
   623→```
   624→
   625→Overpayment = 5,000.
   626→تحدد الإدارة: Refund أو Customer Credit أو Apply to another order.
   627→
   628→## دفع مكرر
   629→
   630→يتم اكتشاف تكرار المرجع/المبلغ/التحويل عند الإمكان، ويظهر Duplicate/Review Flag بدل إنشاء أثر مالي مضاعف.
   631→
   632→## إيصال مشكوك فيه
   633→
   634→يظل Under Review ولا يصبح Verified تلقائيًا.
   635→
   636→---
   637→
   638→# 20. الدفع عند الاستلام
   639→
   640→إن فُعّل:
   641→- لا يعتبر الطلب Paid عند الإنشاء.
   642→- يبقى COD outstanding.
   643→- عند التسليم يسجل التحصيل.
   644→- يتم تسجيل وسيلة التحصيل والحساب المستلم إن لزم.
   645→- في حال فشل التوصيل يعاد الطلب إلى الحالة اللوجستية المناسبة.
